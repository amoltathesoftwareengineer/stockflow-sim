# stockflow-sim

An open-source inventory simulator for balancing overstock against stockouts. Models demand variability, lead times and reorder policies, and benchmarks replenishment strategies on retail data to minimize both holding cost and lost sales.

> **Status:** early development. The simulator, policies and benchmarks are being built in the open. See the [Roadmap](#roadmap).

---

## Why this exists

Every retailer faces the same trade-off:

- **Too much stock** ties up money, takes shelf space, and leads to spoilage or markdowns.
- **Too little stock** means empty shelves, lost sales and unhappy customers.

Deciding *when to reorder* and *how much to order* is hard because demand is uncertain, suppliers are late, and every product behaves differently. Most teams test new rules on live stores, which is risky and slow. Existing tools are either closed or too simple to be realistic.

`stockflow-sim` aims to provide a safe place to test these decisions:

- **A simulator** where a replenishment policy can run for months of virtual trading in seconds.
- **Realistic uncertainty:** random demand, seasonality, promotions, supplier delays.
- **Several reorder policies** under one interface, so they can be compared fairly.
- **Cost-aware metrics:** results show service level and cost together, not one without the other.
- **Reproducible experiments:** the same seed always gives the same result.

## What it simulates

| Element | Examples |
|---|---|
| **Demand** | Daily sales per product and store, with trend, weekly pattern, seasonality and promotion effects |
| **Supply** | Order lead time (fixed or random), minimum order sizes, supplier delays |
| **Inventory** | On-hand stock, stock in transit, backorders or lost sales, shelf life for perishables |
| **Costs** | Holding cost, ordering cost, stockout (lost sale) cost, waste cost |
| **Policies** | The rule that decides when and how much to order |

---

## Data

The simulator can run on three kinds of demand data:

- **Synthetic demand** generated by the project, with configurable patterns
- **Open retail datasets**, for example the M5 Forecasting dataset (Walmart sales), the Favorita grocery sales dataset, and the UCI Online Retail dataset
- **User-supplied CSV files** of historical sales

Datasets are **not** redistributed in this repository. Scripts download them from the original sources, and each dataset keeps its own license and citation requirements.

## Planned approach

### Replenishment policies compared

- **Fixed reorder point and quantity (R, Q):** order a fixed amount when stock falls below a level
- **Min-max (s, S):** order up to a target level when stock falls below a minimum
- **Periodic review (base-stock):** check stock on a schedule and order up to a target
- **Forecast-based:** order using a demand forecast plus safety stock
- **Learning-based (later):** a policy learned by reinforcement learning, compared with the classic rules

### Metrics

- **Fill rate:** share of demand met from stock
- **Stockout days:** how often a product is unavailable
- **Average inventory and inventory turns**
- **Total cost:** holding + ordering + lost sales + waste
- **Cost versus service curve:** how much cost buys each extra point of service level

## How it works

```
demand data (synthetic / open dataset / user CSV)
                    |
                    v
      simulation loop, day by day:
      receive deliveries -> serve demand -> update stock
                    |
                    v
      policy decides: reorder now? how much?
                    |
                    v
      costs and service levels recorded
                    |
                    v
   comparison across policies and settings
```

## Quickstart (planned)

```bash
git clone https://github.com/amoltathesoftwareengineer/stockflow-sim.git
cd stockflow-sim
pip install -r requirements.txt

# run a simulation with one policy
python -m stockflow.run --policy sS --demand synthetic --days 365 --seed 42

# compare several policies
python -m stockflow.compare --policies rq sS base-stock --demand synthetic

# reproduce the benchmark table
python -m benchmarks.run_all
```

## Limitations and responsible use

- A simulator is a simplified model. Real stores have theft, damaged goods, supplier changes and human decisions that are not captured here.
- Results depend on the demand data and cost assumptions. A policy that wins in one setting may lose in another, so always test with your own data.
- Open datasets are limited (sales are not the same as true demand when items are out of stock).
- This project is for research and education. It is not a certified supply planning system.
